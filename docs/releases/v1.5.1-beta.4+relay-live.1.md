# Private-chat live delegation: v1.5.1-beta.4+relay-live.1

Agent A can delegate to Agent B from a private chat without creating a group.
B accepts only when its entire project is idle, then uses its current
conversation and streams normal progress into its registered private chat.
Busy targets reject the task immediately without interruption or queueing.

## Setup

1. In B's Feishu/Lark private chat, an administrator sends `/bind here`.
2. An administrator enables `/relay on` and sends `/bind <B-project>` in A's
   private chat.
3. A uses `cc-connect relay send --to <B-project> --message "task"` to delegate.

`/relay` displays the switch card. The setting covers all projects in one
cc-connect process and survives restart. It is off by default; `/relay off`
preserves legacy Relay behavior. Independent processes have separate switches.
Switch changes affect future dispatches, not tasks already accepted.

## Behavior

- B retains its conversation, workspace, display settings and permission
  policy. Progress, tools, permission prompts and the final reply appear in
  B's registered chat. `/stop` there stops the task.
- Running turns, pending permissions, retries, teardown and another accepted
  delegation count as busy across the project. Concurrent dispatches cannot
  claim the same idle target. Shell schedules also count as activity.
- The final result returns to A while its relay call is waiting. If that wait
  expires, A receives an accepted/still-running receipt and B continues.
  After a timeout, view the eventual result in B's chat; do not resubmit.
- `/bind` lists this source chat's targets, `/bind -<project>` removes one,
  and `/bind remove` clears its live bindings. Legacy bindings stay separate.
- Both private endpoints require their respective bot administrators.
  Re-registering B in a different chat invalidates incoming bindings.
- Delayed or failed delivery of the acceptance notice cannot leave new user
  messages stranded in a queue. Graceful cancellation reports cancellation
  to A instead of successful completion.

This mode supports projects within the same cc-connect instance. Feishu/Lark
provides the required private-chat verification. External CLI processes
outside cc-connect are outside its activity accounting.

## Validation and Updating

The release tag runs web compilation, workflow/format validation, Go build
and vet, the full repository race suite, relay contracts, critical user
journeys and the non-root permission regression before packaging. GitHub
Actions builds Linux, macOS and Windows archives for amd64 and arm64, plus
`checksums.txt`. The updater's archive tests validate checksums and executable
architectures before publication and again against downloaded Release assets.

The beta.4 precedence is newer than beta.3. The update channel remains
`Eitan-S-23/cc-connect`. Check with the corresponding robot's `/upgrade` or
`/update`; installation uses administrator-only `/upgrade confirm` during
authorized maintenance. Publication does not update or restart any instance.

Real Feishu-client interaction and live-instance upgrade acceptance remain
separate from these automated checks. No local compilation is used.
