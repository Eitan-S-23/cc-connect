# Persistent agent preferences: v1.5.1-beta.3+agent-preferences.1

This fork prerelease remembers explicit /mode and /reasoning selections across
cc-connect restarts. Both text commands and selection cards use the same durable
project-state storage.

- The last selection, including a selection of the configured default, wins.
- Preferences are isolated by project, agent type and effective workspace,
  including /dir overrides. Recreated workspace agents restore their choices.
- Existing installations without saved preferences retain configured defaults.
  Unsupported saved values also fall back to those defaults.
- State is saved in the existing data_dir/projects/*.state.json files, without
  rewriting config.toml or provider credentials. Keep data_dir on persistent
  storage when using containers.
- A failed save reports an error and retains the previous selection, session
  history, live session and pending retry. Successful live mode changes retain
  the current conversation.
- Workspace selection cards show and update the resolved workspace agent;
  workspace creation errors no longer change the project's default agent.

Settings keep their existing project/workspace scope, rather than becoming
individual human-user preferences. Choices made with older binaries that never
saved them cannot be recovered retroactively; select them again after updating.

The beta.3 prerelease precedence is newer than beta.2. The authorized update
channel remains Eitan-S-23/cc-connect. The Release (fork) workflow must pass the
web build, formatting, Go build/vet, full repository race tests, critical user
journeys and the non-root permission regression before building six archives:
Linux, macOS and Windows, each for amd64 and arm64, plus checksums.txt.

Isolated Windows preference regressions (including race tests), critical user
journeys, vet and entry-point test compilation passed. The full Windows core
suite still has pre-existing path/home/shell test failures also reproduced on
the prior source. Live Feishu delivery and a production restart are not covered
by this isolated validation.

Publication does not install or restart any instance. Check with /upgrade or
/update on the corresponding cc-connect robot, then use administrator-only
/upgrade confirm when maintenance is authorized. Do not manually replace a
binary or bypass failed CI or updater checks.
